目前城的資料存在本機 localStorage（`ro_idle_castle_1`，同一台的角色共用，模擬伺服器；不會跟雲端存檔一起上傳）。

### 與原規劃的差異
原本第 2 步要把戰鬥函式全面改成「傳入行動者」並拔掉 `withAlly`。實作改用雙世界：
敵方隊伍在自己的 state 裡跑同一套引擎，不必重寫全部戰鬥函式，風險小很多。
`withAlly` 仍保留；之後若要做多隊同場（同一張圖三隊以上），再做全面的行動者改寫。

## 前置重構（原規劃）

| 步驟 | 內容 | 雲端 |
|---|---|---|
| 1. 隊伍快照 | `snapshotParty()`：玩家＋隊友各自的職業、等級、素質、裝備（精煉、卡片）、技能等級、技能格、自動施放設定、站姿 → JSON；`restoreActor(snap)` 還原成可戰鬥角色 | 無 |
| 2. 角色模型＋陣營 | 戰鬥函式改成傳入行動者（不再用 `withAlly` 換全域 `state`）；每個角色有 `side`（我方／敵方）；目標選擇、範圍技、輔助技只看同陣營或敵陣營 | 無 |
| 3. 時間與亂數 | 引擎改用統一的 `now()`／`rng()`；同一份快照＋同一個種子可重播出同一場戰鬥 | 無 |
| 4. 本機攻城原型 | 本機存一份「城主快照」，用自己的舊快照當守城方，驗證方案 B 能打 | 無 |
| 5. 雲端 | 每座城的城主快照、攻城時段、勝負紀錄；上傳前驗證快照（等級、素質總和、道具存在、精煉上限）；可用種子重播驗證勝利 | **先確認** |

步驟 2 也服務 T26 PVP 爬塔與之後的副本。

## 第 2 步的改法（逐步，不一次重寫）

1. 新增 `actorOf(x)`：玩家 state 與隊友物件都當成「行動者」，欄位統一
2. 先改傷害結算（普攻、技能傷害、受傷）吃行動者參數，`withAlly` 暫時保留當轉接層
3. 怪物清單改屬於地圖實例（`MapInstance.monsters`），玩家 state 只留引用
4. 敵對行動者放進地圖實例，與怪物並列為目標；AI 沿用隊友的自動施放
5. 全部改完再拔 `withAlly`
