# 一維戰鬥原型：結果（2026-11-01）

> 對應 `docs/GAMEPLAY_DIRECTION.md` 工作 1。程式：`proto/combat1d/`；資料：`node scripts/gen_proto_data.js`。

## 怎麼跑

```bash
node scripts/gen_proto_data.js
node proto/combat1d/run.js any        # 打斷規則：any / melee / pushback / none
MAX_FIELD=3 node proto/combat1d/run.js any
node proto/combat1d/run.js trace      # 巫師前 30 秒事件
```

**試玩頁**：`python -m http.server 8000` 後開 `http://localhost:8000/proto/combat1d/demo.html`。

- 同一份 `sim.js` 在瀏覽器跑，畫面層只讀模擬狀態與事件（`onEvent`）
- 角色用紙娃娃（`js/paperdoll.js`），可換職業、性別、頭飾；怪物用 `images/mob_anim/`
- 可切換地圖、速度、打斷規則、智能施法、不可中斷
- 職業設定在 `proto/combat1d/classes.js`，`run.js` 與試玩頁共用

## 模型

| 項目 | 做法 |
|---|---|
| 空間 | 怪只記距離 d（格，連續值）；玩家在原點 |
| 怪物 | rAthena `mob_db_re.yml`：HP、ATK、DEF、`WalkSpeed`、`AttackRange`、`AttackDelay`、`DamageMotion`（受擊硬直）、Ai（主動／被動） |
| 技能 | rAthena `skill_db.yml`：詠唱、固詠、後延遲、冷卻、SP、射程、範圍、擊退、`CastCancel`；倍率是 Renewal 約略值 |
| 詠唱 | VCT × max(0, 1 − √((DEX×2+INT)/530)) + FCT；SP 放出時才扣 |
| 火牆 | 距離 w 的一圈；怪越過時吃 50% MATK、擊退 2、扣 1 次（共 12 次） |
| 玩家移動 | 追目標：只縮短目標距離；風箏：所有距離同時增加 |
| 智能施法 | 預估「會打斷的攻擊」在詠唱完成前到達 → 不放這招 |
| 藥水 | 紅、藍各每分鐘最多 10 瓶；喝不夠會死，死亡停 10 秒 |
| 生怪 | 同屏上限 5 隻，每秒補 1 隻，出生距離 6～10 格 |

傷害、命中、角色配點都是簡化版，**只看機制與相對關係，不看絕對數值**。

## 結果（官方打斷規則，同屏 5 隻，3 種子 × 20 分鐘）

**史芬克斯洞穴02**（全近戰怪）

| 職業 | 擊殺/分 | 承傷/分 | 打斷率 | 死亡 |
|---|---|---|---|---|
| 騎士 | 23.1 | 3,582 | — | 0 |
| 獵人 | 33.9 | 5,517 | — | 1 |
| 獵人（風箏） | 23.3 | 334 | — | 0 |
| 巫師（火牆＋風箏＋智能施法） | 13.0 | 167 | 2% | 0 |
| 巫師（無火牆） | 0.0 | 3,234 | — | 2 |
| 巫師（不風箏） | 0.9 | 6,762 | 8% | 29 |
| 巫師（不可中斷） | 13.7 | 487 | 0% | 0 |

**恩芭拉原野01**（含射程 10 的遠程怪）：所有職業每小時死亡 100～190 次；巫師擊殺 0～2/分，「不可中斷」也只有 6.4/分。

## 發現

1. **機制成立**：在全近戰圖，巫師靠「火牆擋＋風箏拉距離＋預判不被打斷」幾乎不受傷、打斷率 2%。拿掉火牆或風箏任何一項就完全打不動。技能組合與 AI 設定因此有實質意義，符合 D2 的目的。
2. **遠程怪是法系的剋星**：射程 10 的怪不會被火牆擋、風箏也拉不開，巫師在恩芭拉幾乎打不了。需要對策（見下方待決）。
3. **後退沒有成本**：一維模型裡後退可以無限進行，多隻怪時 AI 會一直退、不出手（獵人風箏一度只剩 0.9 擊殺/分）。原型用「連續後退 2 秒、冷卻 3 秒」壓住；正式版需要明確規則。
4. **智能施法是必要的**：沒有預判時，巫師在全近戰圖打斷率 100%、擊殺 0。
5. **打斷規則比較**：
   - `melee`（只有近戰打斷）：全近戰圖與官方相同；遠程圖幫助有限，因為遠程怪本身就打得死人
   - `pushback`（受擊延長 20%）：沒火牆的巫師從 0 升到 5.3，但有火牆的反而降到 8.8（智能施法失效、改用硬吃）。技能組合的意義變小
   - 結論：**維持官方規則＋智能施法**
6. **同屏密度**：同屏 5 → 3 隻，恩芭拉的死亡次數只降約 20%。遠程怪的威脅主要來自傷害數值，不是數量。

## 決策（2026-11-01）

| # | 問題 | 決定 |
|---|---|---|
| P1 | 法系如何應付遠程怪 | 不特別處理；玩家靠縮短詠唱、裝備不可中斷效果（劍魚卡等）解決 |
| P2 | 後退的限制 | 後退只用於 Boss 戰閃避範圍技；日常打怪不風箏，清怪不夠快由玩家自行強化 |

## 第二輪：方向角與弧形火牆（2026-11-01）

**改動**

- 怪出生時多記方向角，之後沿自己的方向直線走向玩家（移動仍是一維）
- `angular: true` 時：範圍技用平面距離（餘弦定理）；火牆只擋蓋到的弧，3 格牆蓋住的角度 ≈ 3 ÷ 距離
- 依 P2，日常打怪不風箏；風箏只留一組當參考
- 修正兩個 AI 問題：
  - 火牆可直接放在貼身怪腳下，放下時擊退（原作行為）。先前怪一旦貼身，巫師就永遠脫不了身
  - 智能施法的退路：已被貼身、又沒有別招可放時，照放被跳過的招；有瞬發招或能普攻時優先用那些

**結果：史芬克斯洞穴02（全近戰怪），官方打斷規則，同屏 5 隻**

| 職業 | 擊殺/分 | 承傷/分 | 打斷率 | 死亡 |
|---|---|---|---|---|
| 騎士｜純距離 | 23.0 | 3,581 | — | 0 |
| 騎士｜方向角 | 23.2 | 3,555 | — | 0 |
| 獵人｜純距離 | 33.6 | 5,240 | 0% | 0 |
| 獵人｜方向角 | 24.9 | 1,447 | 0% | 0 |
| 巫師｜圓圈牆 | 16.4 | 2,189 | 31% | 6 |
| 巫師｜弧形牆 | 13.8 | 710 | 10% | 0 |
| 巫師｜弧形牆＋風箏（參考） | 13.0 | 133 | 3% | 0 |
| 巫師｜不可中斷 | 13.7 | 946 | 0% | 0 |

恩芭拉原野01 仍然所有職業都死得很多，待 P4 重測。

**發現**

1. **純距離模型高估範圍技約 25～40%**：方向相反的怪也被算進範圍。加上方向角後，獵人箭雨在史芬克斯 33.6 → 24.9、恩芭拉 31.3 → 18.2；騎士在恩芭拉 31.8 → 22.6。單體技能不受影響（騎士在史芬克斯幾乎不變）
2. **弧形牆比圓圈牆安全**：承傷 2,189 → 710、打斷率 31% → 10%、死亡 6 → 0。原因是弧形牆可以朝不同方向各放一道（上限 3 道），每道各有 12 次；圓圈牆只有一道，所有方向共用次數，很快用完
3. **弧形牆擊殺略低**（16.4 → 13.8）：雷爆術的範圍改用平面距離，打到的怪變少
4. **巫師不靠風箏也能打**：關鍵是「火牆可以放在貼身怪腳下」。巫師 13.8 擊殺/分，約為獵人的 55%，已在 2 倍標準內
5. **早放牆（怪在 9 格內就放）效果不明顯**：圓圈牆 16.4 → 17.1，弧形牆 13.8 → 13.5

**建議**：D1 改為「距離＋方向角」。成本低（怪的移動仍是一維），範圍技與場地技的結果更接近原作；代價是畫面上怪的位置必須與模擬一致，不能只當裝飾。
